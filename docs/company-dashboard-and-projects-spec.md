# اتفاقات وتصور لوحة إدارة الشركة — أسيوط عقار

هذه الوثيقة هي المرجع المعتمد لتطوير مساحة الشركة في منصة **ASYUT AQAR | أسيوط عقار**. يجب الحفاظ عليها عند تنفيذ المراحل التالية، وعدم تغيير القرارات الواردة فيها إلا بعد موافقة صاحب المشروع.

## 1) نموذج عرض البيانات المعتمد

اعتماد النموذج الهجين التالي:

**ملف الشركة ← ملخص المشروعات ← صفحة مستقلة لكل مشروع ← الوحدات والإعلانات المرتبطة به.**

- ملف الشركة يعرض هويتها وبياناتها وخدماتها وفروعها وفريقها وملخص مشروعاتها.
- لكل مشروع سجل مستقل وصفحة عامة مستقلة.
- لكل وحدة أو عرض عقاري سجل/إعلان مستقل، ويمكن ربطه بمشروع.
- إذا لم تكن الوحدة تابعة لمشروع، يمكن عرضها كإعلان مستقل.
- لا تُعامل الوحدة باعتبارها مشروعًا، ولا يُعامل المشروع باعتباره إعلان وحدة.
- لا تُكرر بيانات الوحدة في أكثر من سجل؛ صفحة المشروع تعرض الوحدات المرتبطة بها.

## 2) اختلاف صلاحيات الشركات

### شركات التطوير العقاري
- تدير ملف الشركة.
- تضيف مشروعاتها التي تثبت صفتها فيها، بعد المراجعة.
- تنشئ لكل مشروع صفحة مستقلة، ثم تربط الوحدات والعروض بالمشروع.
- لا يُعرض المشروع على أنه تابع للمطور لمجرد إدخال اسمه؛ يلزم تحقق الصفة أو التفويض.

### شركات التسويق والوساطة
- تدير ملف الشركة وخدماتها وفروعها ومناطق التغطية.
- تضيف أو تدير العروض التي تملك حق تسويقها أو الوساطة فيها وفق الصلاحيات والمراجعة.
- يمكن ربطها بمشروع بصفتها **وكيل تسويق** أو **وكيل مبيعات** عند وجود تفويض موثق.
- لا تظهر بصفتها المطور، ولا تنشئ نسخة مكررة من المشروع لمجرد تسويقه.

## 3) مكونات لوحة الشركة

- **نظرة عامة:** حالة ملف الشركة، ملخص المشروعات، ملخص الوحدات والإعلانات، وطلبات المراجعة.
- **بيانات الشركة:** الاسم والشعار والنبذة والنوع ووسائل التواصل والفروع ومواعيد العمل والخدمات ونطاق التغطية.
- **المشروعات:** قائمة مشروعات الشركة، حالة كل مشروع، إضافة مشروع، وفتح صفحة المشروع المستقلة.
- **الوحدات والإعلانات:** إضافة وحدة، تعديل العروض المصرح بها، وربط الوحدة بمشروع أو إبقاؤها إعلانًا مستقلًا.
- **فريق العمل:** إدارة أعضاء مفوضين بأدوار محدودة.
- **المراجعات:** حالة الطلبات وملاحظات الإدارة وإعادة الإرسال عند طلب الاستكمال.

## 4) استلام الملف والتحقق

1. يفتح الممثل ملف الشركة المنشور ويضغط «استلم ملفك مجانًا».
2. يسجل الدخول ويقدم اسمه وصفته ووسيلة التواصل وما يثبت علاقته بالشركة أو تفويضه.
3. تراجع إدارة أسيوط عقار الطلب.
4. يمكن للإدارة اعتماد الطلب أو طلب استكمال البيانات أو رفضه مع توضيح السبب.
5. لا تُمنح أي صلاحية بمجرد تقديم الطلب؛ لا تفعيل إلا بعد التحقق وموافقة الإدارة.
6. ممثل الشركة المعتمد يدير ملف الشركة والمشروعات والعروض المصرح بها فقط.
7. أي موظف إضافي يحتاج دعوة وصلاحية محددة، ويمكن إلغاء صلاحياته.

## 5) الأدوار المقترحة

- **المالك أو الممثل المعتمد:** إدارة الملف، دعوة الفريق، واعتماد التغييرات الداخلية المسموح بها؛ مع بقاء التغييرات الحساسة خاضعة لموافقة إدارة أسيوط عقار.
- **مدير ملف مفوض:** إدارة العناصر التي يمنحها له الممثل المعتمد، ضمن نطاق الشركة فقط.
- **محرر بيانات:** تعديل الحقول التشغيلية التي تسمح بها صلاحياته فقط.
- لا يستطيع أي عضو إدارة ملف شركة أخرى أو نقل ملكية ملف.
- الصلاحيات الفعلية يجب أن تُفرض من الخادم وRLS/RPC، ولا يكفي إخفاء الأزرار في المتصفح.

## 6) المراجعة والنشر

- ملف الشركة أو المشروع أو الإعلان الجديد لا يُنشر تلقائيًا عند الإرسال.
- حالة الطلب وملاحظات الإدارة تظهر بوضوح لصاحب الصلاحية.
- التغييرات الحساسة (مثل اسم الجهة أو وسائل التواصل الأساسية) تبقى غير منشورة حتى الاعتماد.
- تُحفظ سجلات المراجعة والتعديلات، ولا تُمحى البيانات القديمة لمجرد طلب تحديث.
- لا نخلط بين التحقق من ممثل الشركة وبين إثبات الترخيص القانوني للشركة.

## 7) قواعد بيانات الدليل والمشروعات الحالية

- لا يُعاد تصنيف أو حذف أو استبدال بيانات الدليل المنشورة تلقائيًا.
- النصوص الحالية التي تحتوي أسماء مشروعات داخل ملف الشركة تُعامل كسابقة أعمال/وصف معلوماتي، وليست سجلات مشاريع مستقلة.
- لا تتحول تلك النصوص إلى مشروعات معتمدة إلا بعد مراجعة يدوية لمصدرها وصفة الشركة.
- يجب الحفاظ على مصادر المعلومات والتنويه عن البيانات غير المؤكدة.
- لا تُعرض مواقع دقيقة على الخريطة إلا عندما تكون موثقة ومسموحًا بنشرها.

## 8) الدقة والشفافية

- لا يُقال إن شركة مرخصة لمجرد أن ممثلها تم التحقق منه.
- لا يُنسب مشروع إلى مطور أو وكيل دون إثبات الصفة.
- لا يُعلن عن وحدات متاحة أو أسعار أو مراحل إنجاز دون بيانات موثقة.
- يجب توضيح الفرق بين المطور ووكيل التسويق ووكيل المبيعات.
- لا تُعرض مؤشرات أو أعداد وهمية؛ الأرقام في اللوحة تأتي لاحقًا من بيانات حقيقية ومصرح بها فقط.

## 9) نطاق العمل وترتيب التنفيذ

1. تصميم لوحة الشركة الرئيسية وتجربة الهاتف.
2. ربط بيانات الشركة الحقيقية والصلاحيات الموجودة.
3. استكمال إدارة المشروع وإنشاء صفحة مستقلة له.
4. ربط الوحدات والإعلانات بالمشروعات وبملفات الشركات.
5. تمكين شركات التسويق من الارتباط بالمشروعات بصفتها التسويقية الموثقة.
6. اختبارات الصلاحيات والمراجعة والنشر، ثم اعتماد التغييرات قبل الدمج والنشر.

شركات الخدمات والموردون والتشطيبات والأثاث تظل خارج نطاق لوحة الشركات العقارية حتى اكتمال ومراجعة الشركات العقارية.

## 10) قواعد الهوية والحماية للمراحل التالية

- الحفاظ على شعار أسيوط عقار الأصلي دون تعديل ملفاته أو الأصول التابعة له.
- الالتزام بالمظهر والألوان الحالية للمنصة وتوحيد التباعد والخطوط والحالات، دون إعادة تصميم الهوية من الصفر.
- الواجهة عربية RTL ومتجاوبة مع الهاتف أولًا.
- لا تغيير في قاعدة الإنتاج أو RLS أو Auth أو الأدوار أو الأسرار أو الدومين دون موافقة صريحة منفصلة.
- لا دمج ولا نشر إلى الإنتاج دون اعتماد صاحب المشروع.
- أي تنفيذ يبدأ بالفحص، ثم فرع مستقل، ثم اختبارات ومراجعة قبل طلب الاعتماد.

## 11) المرحلة المتصلة الأولى للوحة الشركة

أصبحت الملفات التالية هي واجهة لوحة الحساب الخاصة:

- **company-dashboard.html**: صفحة اللوحة الخاصة، مع `noindex,nofollow`.
- **assets/theme/company-dashboard.css**: تنسيق متجاوب للهاتف وسطح المكتب، متوافق مع نمط صفحة الشركات وألوانها الحالية.
- **company-dashboard.js**: قراءة البيانات بعد التحقق من جلسة الحساب، مع استخدام واجهات الوصول الحالية.

### ما تعرضه اللوحة الآن

- ملف الشركة المقدم من الحساب عبر `layan_company_owner_profile`، دون قراءة جدول `company_profiles` مباشرة.
- ملفات الدليل التي ثبتت صلة الحساب بها كمالك أو عضو فريق، وفق سجلات الربط التي تسمح RLS للحساب بقراءتها.
- المشروعات المنشورة فقط والمرتبطة بكيانات الدليل من خلال `directory_project_entities`، مع عرض صفة الشركة مثل المطور أو وكيل التسويق أو وكيل المبيعات.
- إعلانات الحساب التي يستطيع صاحب الحساب قراءتها، مع توضيح أنها ليست منسوبة للشركة أو للمشروع تلقائيًا.
- سابقة الأعمال النصية داخل ملف الشركة مع تنويه صريح بأنها ليست سجلات مشروعات مستقلة.
- فريق ملف الشركة أو الجهة للمالك الأساسي المعتمد فقط، من خلال RPCs الحالية لدعوة أعضاء الفريق وعرضهم وإلغاء صلاحياتهم.

### ما لا تفعله اللوحة بعد

- لا تنشئ مشروعًا جديدًا ولا تعدل سجلات `directory_projects`.
- لا تربط إعلانًا بمشروع أو ملف شركة؛ فالعلاقة غير موجودة في مخطط `property_offers` الحالي.
- لا تسمح للعضو المفوض بدعوة أعضاء آخرين أو إلغاء صلاحياتهم.
- تعرض طلبات الاستلام والتحديث الخاصة بالحساب فقط، ولا تقرأ قوائم طلبات بقية المستخدمين.
- لا تعدل بيانات الهوية أو التواصل من داخل اللوحة؛ الروابط تفتح مسارات التحرير الحالية. التغييرات الحساسة تظل خاضعة لمراجعة الإدارة.
- لا تعرض عدادات أو معلومات شركة غير مرتبطة بجلسة المستخدم الحالية.

لم تُضف أي Migration أو جدول أو Policy أو Grant أو RPC جديد في هذه المرحلة. كل قراءات اللوحة تمر عبر الجلسة المصادق عليها وRLS وواجهات RPC الموجودة. عمليات دعوة الفريق أو إلغاء الصلاحية لا تحدث إلا عندما يختار المالك المعتمد تنفيذها من الشاشة.

## 12) الاختبارات والحدود

أضيفت اختبارات متصفح للوحة تغطي عرض ملف الشركة وملف الدليل، وصفة وكيل التسويق، والمشروعات المنشورة، وإعلانات الحساب، ودعوات فريق الملف، والحساب الذي لا يملك ملفًا، وحالة الزائر غير المسجل. يجب انتظار نتيجة GitHub Actions النهائية قبل اعتماد الاختبارات.
