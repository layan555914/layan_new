# المرحلة الرابعة — وحدات المشروعات وربط الإعلانات

**الحالة:** يؤكد سجل ترحيلات Supabase الإنتاجي تطبيق Migration `20261118055155` باسم `project_units_and_offer_associations`، كما أن جدول `directory_project_units` ووظائف طلبات الوحدات وربط الإعلانات موجودة. جرى توصيل واجهاتها بملف الجهة المنشور مع بقاء نشر واجهة الملف رهناً باجتياز الاختبارات وموافقة صاحب المنصة.

## 1. العلاقة المعتمدة

تسلسل البيانات أصبح واضحًا ومفصولًا:

**ملف الشركة المعتمد ← علاقة المطوّر/مالك الأرض بالمشروع ← سجل وحدة منشور ← إعلان عقاري مرتبط صراحة بالوحدة.**

سجل المشروع يظل مستقلًا عن الإعلان. الإعلان لا يكتسب صفة «تابع للمشروع» لمجرد أن حقل `project_name` أو `developer_name` يحتوي على اسم قريب أو مطابق.

## 2. تسجيل الوحدات من الشركة

داخل ملف شركة التطوير المنشور يوجد قسم «وحدات المشروعات». يستطيع المالك المعتمد أو مدير الملف المفوض تقديم طلب وحدة عندما تكون الشركة مرتبطة بسجل المشروع المنشور بصفتها مطورًا أو مالك أرض.

على ممثل الشركة اختيار **المشروع وملف الشركة المرتبط به صراحةً** في نفس الطلب. هذا مهم عند ارتباط أكثر من ملف شركة بالمشروع نفسه؛ لا يستنتج النظام الشركة من حساب المستخدم وحده. يتحقق الخادم من أن المستخدم مالك أو مدير للملف الذي اختاره، وأن ذلك الملف نفسه مرتبط بالمشروع بصفة المطوّر أو مالك الأرض. البيانات المطلوبة تشمل كود الوحدة أو ما يميزها، النوع، المبنى، الدور، رقم الوحدة، المساحة، غرف النوم والحمامات، التشطيب والوصف. يرفق الممثل رابطًا عامًا أو وصفًا لدليل البيانات.

لا تُنشأ الوحدة في المخزون العام بمجرد الإرسال. يُخزن الطلب في مخطط `private`، ولا يستطيع المحرر إرساله، ولا يستطيع أي مستخدم الكتابة المباشرة إلى جدول الوحدات.

## 3. مراجعة الإدارة ونشر الوحدة

تظهر الطلبات في صفحة «إدارة وحدات المشروعات وربط الإعلانات» المرتبطة بمركز إدارة الدليل. للإدارة ثلاثة قرارات: اعتماد، طلب استكمال، أو رفض.

عند الاعتماد تتحقق الوظيفة من أن المشروع وملف الشركة ما زالا منشورين وأن العلاقة ما زالت بصفة المطور أو مالك الأرض، ثم تنشئ سجل الوحدة المنشور داخل المشروع. الطلبات وملاحظات الإدارة لا تُعرض للعامة.

## 4. ربط إعلان عقاري بوحدة

داخل ملف الشركة يستطيع صاحب الحساب طلب ربط إعلان منشور ومتاح يملكه بوحدة منشورة في أحد مشروعات الملف. وتظل صفحة «إعلاناتي» مسارًا متاحًا لصاحب الإعلان أيضًا.

يراجع مسؤول الإدارة الطلب. عند الموافقة فقط تكتب الوظيفة قيمة `property_offers.project_unit_id`، وهي مفتاح أجنبي إلى سجل الوحدة. لا يملك المستخدم العادي صلاحية تحديث هذا الحقل، ويوجد Trigger يمنع إدخاله عند إنشاء الإعلان أو تغييره مباشرة دون مسار موافقة الإدارة.

## 5. العرض العام

صفحة المشروع تعرض:
- الوحدات المسجلة والمعتمدة فقط.
- الإعلانات المتاحة المرتبطة صراحة بكل وحدة فقط.
- حالة عدم وجود وحدات أو إعلانات مرتبطة عندما لا توجد سجلات منشورة.

لا تعرض صفحة المشروع إعلانات لمجرد تطابق اسم المشروع المكتوب في الإعلان. كما لا تعرض الإعلانات المحجوزة أو المباعة أو المؤجرة في قائمة العروض المتاحة.

## 6. السجلات القديمة

- العمود الجديد `project_unit_id` يقبل NULL.
- لا يوجد ترحيل تلقائي أو backfill بناءً على `project_name` أو `developer_name`.
- الإعلانات الحالية تظل كما هي، ولا يتغير أي سعر أو حالة أو مالك أو نص.
- يمكن ربط إعلان قديم لاحقًا بطلب صريح من صاحبه وبعد مراجعة الإدارة.

## 7. ضوابط قاعدة البيانات

Migration: `20261118000300_project_units_and_offer_associations.sql`

- `public.directory_project_units`: سجلات وحدات عامة للقراءة فقط، وتظهر فقط عندما تكون الوحدة والمشروع منشورين.
- `private.company_project_unit_requests`: طلبات تسجيل الوحدات، مخفية عن Data API المباشر.
- `private.property_offer_project_unit_requests`: طلبات الربط، مخفية عن Data API المباشر.
- وظائف `private` ذات الامتياز من نوع `SECURITY DEFINER`، مع أغلفة RPC عامة من نوع `SECURITY INVOKER`.
- تنفيذ RPC متاح للمستخدم المسجل فقط؛ الأدوار تُفحص في الخادم.
- لا تمنح هذه المرحلة صلاحية تعديل عامة على `property_offers` أو `directory_project_units`.

## 8. الاختبارات المضافة

- `tests/db/project-units-and-offer-associations-smoke.sh`: اختبار PostgreSQL معزول لمسار المالك والمدير والمحرر، موافقة نشر الوحدة، ربط الإعلان بعد موافقة الإدارة، منع التعديل المباشر، بقاء إعلان الاسم النصي دون ربط، وحدود العرض العام.
- `tests/e2e/project-units-phase4.spec.mjs`: اختبار نماذج الشركة وصاحب الإعلان وصفحة المشروع وصفحة مراجعة الإدارة.
- سير عمل GitHub Actions يشغل اختبار قاعدة البيانات المعزول بعد اختبارات المرحلتين الثانية والثالثة.

## 9. حدود المرحلة

لا تتضمن هذه المرحلة إدارة أسعار الوحدات أو المخزون المتاح أو الحجز أو السداد أو التعاقد. الإعلان يظل هو مصدر السعر والحالة التسويقية. كما لا تشمل رفع مستندات ملكية حساسة إلى حقول عامة؛ المستندات التفصيلية تتطلب قناة مراجعة آمنة منفصلة.

## 10. بوابة الإنتاج

يجب أن تنجح اختبارات PostgreSQL والمتصفح على فرع التطوير، ثم تُراجع Migration وسياسات RLS والوظائف والواجهات. لا تُطبق Migration على Supabase الإنتاجي ولا يُدمج الفرع ولا يُنشر إلا بموافقة صريحة منفصلة.
