# مقترح ربط مواقع المطورين والمشروعات بالخرائط — 3 نوفمبر 2026

## الحالة
**مقترح مراجعة فقط — غير مطبق على قاعدة الإنتاج.**
لم تُنفذ أي أوامر SQL أو تغييرات في RLS أو صلاحيات Supabase. لا تُعرض نقاط مواقع فردية قبل اعتماد حقول الموقع ومصدر الإحداثيات واختبار صلاحيات القراءة.

## ما هو موجود الآن
- خريطة العقارات في الصفحة الرئيسية تقرأ خط العرض والطول للعقار، ولا ترسم علامة عند غياب الإحداثيات.
- صفحات الدليل والشركات تعرض خريطة تفاعلية عامة لمدينة أسيوط وروابط بحث حسب المنطقة أو اسم النشاط.
- جداول الدليل الحالية لا تحتوي على إحداثيات للجهات أو المشروعات أو المناطق؛ لذلك لا يجوز اعتبار دبوس وسط المدينة موقعًا لمطور أو مشروع.

## تصميم البيانات المقترح
إضافة حقول الموقع التالية إلى `directory_entities` و`directory_projects` و`directory_areas` بعد مراجعة واعتماد منفصل:

| الحقل | النوع | الغرض |
|---|---|---|
| `map_latitude` | `numeric(9,6)` | خط العرض |
| `map_longitude` | `numeric(9,6)` | خط الطول |
| `map_location_kind` | `text` | نوع النقطة: موقع رسمي، عنوان منشور، أو مرجع نطاق جغرافي |
| `map_source_id` | `uuid` | المصدر الذي يثبت الموقع، ويرتبط بـ `directory_sources.id` |
| `map_accuracy_meters` | `integer` | نطاق دقة الموقع بالمتر عند معرفته |
| `map_verified_at` | `date` | تاريخ التحقق من الإحداثيات |

### ضوابط البيانات
1. خط العرض والطول إما كلاهما فارغ أو كلاهما موجود.
2. خط العرض بين -90 و90، وخط الطول بين -180 و180.
3. لا تُحفظ إحداثيات منشورة دون مصدر مرتبط، ويجب أن يكون المصدر عامًا `is_public=true`.
4. لا تُعرض نقطة الجهة أو المشروع إلا عندما يكون السجل نفسه `public_visible=true` و`verification_status='published'`.
5. `area_reference` تعني نقطة مرجعية للمنطقة فقط، وليست عنوان شركة أو مدخل مشروع.
6. الدبوس الدقيق لا يستخدم إلا مع مصدر يثبت موقع المقر أو الموقع المنشور؛ نتائج البحث في أدلة الأعمال لا تكفي وحدها.
7. لا يُنسخ عنوان مرشح أو رقم هاتف داخلي من جداول المراجعة إلى بيانات عامة.
8. كل تعديل إحداثيات يسجل في `directory_change_log` ويحتاج سببًا ومراجعة مسؤول.

## سير عمل لوحة الإدارة المقترح
- حقلان رقميان للإحداثيات، مع التحقق من النطاق وعدم قبول أحدهما منفردًا.
- اختيار نوع الموقع من قائمة واضحة.
- اختيار مصدر عام موجود في قاعدة المصادر، مع زر لفتحه ومراجعته.
- توضيح حالة النقطة: موقع رسمي / عنوان منشور / مركز منطقة.
- معاينة الخريطة قبل الحفظ، ثم حفظ وتسجيل أثر التعديل.
- يمنع النشر إذا كان مصدر الموقع غير عام أو لم تكتمل مراجعة النقطة.

## واجهة الزائر المقترحة
- إظهار علامات الجهات والمشروعات التي لها إحداثيات ومصدر موقع عام فقط.
- نافذة العلامة تعرض الاسم والنوع والمنطقة ونوع الموقع ورابط مصدر الموقع.
- تمييز مرجع المنطقة عن موقع المقر أو المشروع.
- عند غياب الإحداثيات، يظهر رابط بحث باسم الجهة أو المشروع في خرائط Google بدل دبوس تخميني.
- عدم تخزين مربعات خرائط OSM أو تنزيلها مسبقًا دون إذن؛ الإسناد إلى OpenStreetMap ظاهر دائمًا.

## الاختبارات المطلوبة قبل اعتماد التغيير
- سجلات بلا إحداثيات لا تظهر كعلامات.
- رفض إحداثيات خارج النطاق أو إحداثية واحدة فقط.
- رفض مصدر داخلي أو مصدر غير موجود.
- إخفاء العلامة عند إخفاء السجل أو إعادته للمراجعة.
- التحقق من عدم قدرة الزائر أو المستخدم العادي على تعديل الإحداثيات أو قراءة ملاحظات المراجعة الداخلية.
- اختبار فتح الخريطة والروابط على هاتف بعرض 375px وعلى شاشة كمبيوتر.
- اختبار المصدر داخل نافذة العلامة والتأكد من أن نوع الموقع ظاهر بوضوح.

## قرار التنفيذ
يظل هذا المقترح خارج migrations التنفيذية. لا يُطبق أي تعديل على Supabase production إلا بعد موافقة صريحة على تصميم الحقول والسياسات، ثم ينفذ في فرع تطوير واختبارات منفصلة أولًا.
