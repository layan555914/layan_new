# مراجعة وتنفيذ لوحة إدارة دليل أسيوط — staging
التاريخ: 3 نوفمبر 2026

## النتيجة الحالية
- تم نشر RPC `public.directory_admin_mutate_with_audit(text,text,uuid,jsonb,text)` على قاعدة الاختبار `layan-claude-test` فقط.
- الدالة تنفذ تعديل السجل وسجل التدقيق ضمن معاملة واحدة، باستخدام `SECURITY INVOKER` وقائمة جداول/حقول مسموح بها.
- لم يتم نشر الدالة على قاعدة الإنتاج ولم يتم تعديلها.
- لا يوجد دمج أو نشر للموقع. PR #42 ما زال Draft ومفتوحًا.

## نتائج اختبار قاعدة staging
تم الاختبار على بيانات اصطناعية موجودة مسبقًا، داخل معاملة واحدة انتهت بـ `ROLLBACK`:
1. المستخدم غير المسؤول: رفض RPC بالرمز `42501`.
2. عضوية مسؤول مؤقتة داخل المعاملة: `public.layan_is_admin() = true`.
3. تحديث جهة مع إعادة السجل و `audit_id`: PASS.
4. إضافة مصدر اصطناعي خاص ثم تسجيل أثره: PASS.
5. ربط المصدر بالجهة ثم تسجيل أثره: PASS.
6. رفض تمرير حقل المفتاح الأساسي `id` ضمن التعديل: PASS.
7. فرض فشل إدراج سجل التدقيق، والتحقق أن تحديث الجهة نفسه تراجع: PASS.
8. عدد سجلات التدقيق للعمليات الناجحة داخل المعاملة: 3 كما هو متوقع.

## التنظيف والتحقق بعد الاختبار
الاستعلام اللاحق أكد:
- `private.layan_admins`: صفر مسؤولين.
- `auth.users`: مستخدم واحد كما كان قبل الاختبار؛ لم يُنشأ مستخدم Auth جديد.
- `directory_sources`: سجل واحد كما كان قبل الاختبار.
- `directory_entity_sources`: رابط واحد كما كان قبل الاختبار.
- `directory_change_log`: صفر سجلات اختبار.
- لا يوجد مصدر أو رابط بعلامة الاختبار.
- وصف الجهة الاصطناعية عاد إلى النص الأصلي.

**بخصوص موافقتك على حساب اختبار مؤقت:** لم أستخدم حسابك الحقيقي ولم أغيّر كلمة مروره أو صلاحياته بشكل دائم. أُجري اختبار دور المسؤول بإضافة عضوية مؤقتة لهوية staging الموجودة فقط داخل معاملة واحدة، ثم ألغى `ROLLBACK` الإضافة وكل التغييرات. إنشاء مستخدم Auth منفصل عبر `auth.admin.createUser` يتطلب مفتاح Supabase السري في بيئة خادم موثوقة؛ هذا المفتاح غير متاح عبر أدوات الاتصال الحالية، ولم أحاول استخراجه أو وضعه في ملفات عامة. لذلك لم يحدث تسجيل دخول حقيقي من متصفح إلى لوحة الإدارة بحساب جديد.

## التحقق الأمني بعد إضافة RPC
- `SECURITY INVOKER`: true for caller privileges (الدالة ليست SECURITY DEFINER).
- `anon` لا يملك EXECUTE.
- `authenticated` يملك EXECUTE؛ وتتحقق الدالة من `auth.uid()` ومن `public.layan_is_admin()` قبل أي تغيير.
- سياسات RLS على الجداول بقيت كما هي.
- مستشار Supabase لم يظهر تحذيرًا أمنيًا جديدًا بسبب الدالة.
- التحذيرات السابقة ما زالت قائمة دون تعديل:
  - Leaked Password Protection معطل.
  - أربع جداول RLS مفعّل عليها دون سياسات، وهي مغلقة افتراضيًا.
  - تحذير سياسة قراءة متعددة على `company_profiles`.
  - unused indexes: 25 في قاعدة الاختبار.
