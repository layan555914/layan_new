## نتائج مراجعة PostgreSQL وRLS
- حالة مشروع Supabase: `ACTIVE_HEALTHY`، ومحرك PostgreSQL 17.11.
- رابط المشروع ومفتاح النشر العام في `config.js` يطابقان إعدادات المشروع، والمفتاح نشط.
- RLS مفعّل على جداول العروض والمفضلة وتفضيلات المشتري والتنبيهات وملفات الشركات وسوق الخدمات.
- صلاحية `anon` لقراءة جداول المفضلة وتفضيلات المشتري واشتراكات Push وبيانات VAPID غير ممنوحة.
- صلاحية استخدام مخطط `private` غير ممنوحة لـ `anon`.
- اختُبر دور `anon` داخل معاملة SQL للقراءة فقط؛ ظهرت الأقسام العامة الـ11، ولم تظهر عروض عامة متاحة وقت الفحص.
- اختُبر دور `authenticated` بمحاكاة JWT لمعرّف اصطناعي؛ أعادت `layan_is_admin()` القيمة `false`، ولم تظهر له إعلانات أو مفضلات مملوكة. هذا اختبار لسياسات Postgres وليس تسجيل دخول حقيقيًا.
- دوال الإدارة والإشعارات المنشورة (`asyut-admin`, `asyut-push`, `layan-ai`) حالتها ACTIVE وتتطلب JWT.

## نتائج Supabase Advisors
1. **تحذير أمان:** ميزة Leaked Password Protection غير مفعّلة. لم أغيّر إعدادات Auth أو كلمات المرور أو صلاحيات الحسابات.
2. **ملاحظات RLS دون سياسة:** أربع جداول مغلقة افتراضيًا بسبب RLS وعدم وجود سياسات مباشرة: `private.layan_admins`, `private.project_decisions`, `public.buyer_push_subscriptions`, `public.buyer_push_vapid_config`. فحص منح الصلاحيات أكد أن المستخدمين العاديين لا يستطيعون قراءة جدولي Push؛ مسارات الخدمة تعتمد على Edge Functions.
3. **تحذير أداء:** جدول `company_profiles` لديه سياستان متساهلتان لقراءة SELECT لدور authenticated (إحداهما للإدارة والأخرى لنطاق القراءة). هذه ملاحظة أداء، لا دليل على تسريب، ولم أغيّر السياسة خلال فحص الاتصال.
4. ظهرت 16 ملاحظة INFO عن فهارس غير مستخدمة؛ جداول عديدة لا تحتوي بيانات حاليًا، ولذلك لا أوصي بحذف فهارس قبل وجود حركة فعلية وقياس الأداء.

## ما لم يتم اختباره بعد
- لم يتم إنشاء حساب اختبار حقيقي؛ لا توجد رسالة تأكيد بريد يمكنني استلامها أو التحقق منها من خلال هذه الأدوات.
- لم يتم اختبار تدفق التسجيل/تأكيد البريد/تجديد الجلسة بكلمة مرور حقيقية أو رمز JWT صادر من Auth.
- لم يتم تنفيذ إدخال إعلان حقيقي أو رفع صور/مستندات إلى Storage أو إرسال Push إلى جهاز فعلي.
- الاختبار الحي الحالي قراءة عامة ورفض وصول مجهول فقط؛ لا يثبت وصول مستخدم حقيقي إلى سجلاته أو منع مستخدم حقيقي من سجلات مستخدم آخر.
- لم يتم فحص DNS أو HTTPS أو نشر GitHub Pages في هذا الاختبار.
